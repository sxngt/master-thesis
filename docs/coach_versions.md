# 보상 코치 v1 → v5 — 리포트·판단층·아키텍처의 변천과 v5 설계 (2026-09-07)

코치는 PPO 학습(내부 루프)을 건드리지 않는 외부 루프다. 매 `interval_steps`(2M)마다
결정적 평가 → 리포트 → 스케줄러(llm | random | hillclimb | none) 제안 → 가드레일 →
적용, 다음 리포트에서 J가 떨어졌으면 롤백. 코드는 `llm_feedback/coach.py`
(판단층·리포트), `llm_feedback/coach_stats.py`(v5 통계층), `llm_feedback/prompts.py`,
설정은 `configs/coach/*.yaml`. 모든 프롬프트/응답 원문은 `<run_dir>/coach_log.jsonl`.

아래의 v1–v4 항목은 각 배치의 `coach_log.jsonl`에 기록된 실제 프롬프트를 diff한 것이다
(`data/results/coach_batch|coach_v2|coach_v3|coach_v4`).

## 2. 버전별 상세

### v1 — 최초 (`9171af0`)
- **리포트**: KPI 8개(성공률·속도·CoT·경로효율·자세안정·낙상빈도·접촉력분산·토크효율),
  학습통계(gait/*, attitude/*, motion/*, episode/fall_fraction, reward/<항>), PPO 동역학
  (actor_std, approx_kl, kl_penalty, loss), 개입 이력 12건.
- **프롬프트 규칙**: 파라미터 ≤3, 선형 ±30 %/로그 ×3, 부호 잠금, 0.05 롤백. "추세가
  건강하면 바꾸지 마라, 한 항이 지배하면 한 번의 결정적 변경".
- **판단층**: 롤백만. best 스냅샷 없음.
- **무엇이 틀렸나**: 평가가 "먼저 끝난 20 에피소드"라 빨리 넘어진 env가 표본을 독점 —
  성공률이 0↔1로 요동. 목표 도달 후에도 에피소드가 계속돼 잘 걷는 정책이 지형
  가장자리에서 떨어져 "낙상"으로 집계 → LLM이 termination/stability만 키우는 헛수.
  (`docs/findings.md` §3.6-1,2)

### v2 — 측정 수정 + 복원 (`coach_v2`)

- **리포트 추가**: `## Task`(지형·레벨·5 m/20 s·낙상 종료·env 수), 목적 궤적(모든 평가의

  의미, actor_std 해석, "한 점이 아니라 추세로 판단").
- **조정 대상 추가**: `algo.learning_rate`, `algo.entropy_coef`(live PPO 하이퍼).
- **출력 추가**: `restore_best`(best 스냅샷 복원; J가 best보다 허용치 이상 낮을 때만 유효).
- **hillclimb**: 개선 없는 유지 개입을 되돌리는 undo 추가(에너지 가중치 래칫 ×28 방지).
- **무엇이 틀렸나**: 결정적 리셋으로 1024 env가 같은 궤적 → 유효표본 4개, J가 0.25

  best로 기록돼 같은 스냅샷을 7회 복원(14M 스텝 소실). (§3.6-3,4)

### v3 — 리셋 임의화 + 커리큘럼 레버 (`coach_v3`, 정본 대조군)
- **측정**: `sim.reset_noise`(위치 ±0.5 m, 요 ±π, 속도 ±0.3, 관절 ×[0.8,1.2]) → 잡음

- **조정 대상 추가**: `forward_velocity.target_ms`(0.3–1.5). 프롬프트에 "목표 속도는
  커리큘럼 레버: 낮추면 v≈0에서 기울기를 얻고, 게이트가 안정되면 올려 속도를 산다".
- **판단층**: v2와 동일.
- **결과**: rough-hard 10/10 시드가 none 최고 시드보다 높음; naive에서 none 15/15 실패

- **무엇이 틀렸나**: stairs에서 런당 복원 3.4회, 시드 2는 10M 스냅샷을 5회 복원 → 학습
  시간 삭제. 판단이 아니라 판단층의 구조(복원 무제한) 문제. (§3.6-5)

### v4 — 잡음 인지 판단층 (`coach_v4`)
- **판단층**: 허용치 = min(max(0.05, 2·√2·σ̂), 0.3), σ̂ = 1.4826·MAD(2차 차분)/√6(선형

- **리포트 추가**: "Noise: σ̂, 이보다 작은 차이는 잡음, 현재 유효 허용치".
- **프롬프트 추가**: 허용치 자동 확장 안내, 복원 제한과 그 이유, "초기 전부 낙상 구간은

- **무엇이 틀렸나**: (a) stairs 5/5 시드가 `target_ms`를 0.7로 내린 뒤 되올린 기록 0건 →

- **v4.1**(구현, 미실행): 목적함수 분해(항별 기여 + `kpi_command` 상한·추종률), "내린
  목표는 되올려라" 규칙, API 오류 재시도 3회 후 리포트 스킵.

## 3. v5 설계 — "추측하지 말고 계산해서 보여준다"

v1–v4의 결함은 모두 한 종류다: **LLM이 판단해야 할 것을 시스템이 계산해서 주지 않았고,
시스템이 지켜야 할 것을 LLM의 판단에 맡겼다.** v5는 판단층에 통계 모형을 넣고, 리포트에
계산된 증거를 넣고, 목적함수의 항을 잃는 일은 불변식으로 막는다. 스케줄러 4종(llm /
random / hillclimb / none)이 판단층을 공유하므로 비교의 공정성은 유지된다.

### 3.1 측정 모형과 롤백 검정
평가 k의 관측 J_k = J*_k + ε_k, ε_k ~ N(0, σ_k²).

- 측정 분산(평가 1회 내부): σ²_meas = Σ_m w_m² SE_m², SE_success = √(p(1−p)/n) (p는
  [1/n, 1−1/n]로 바닥), SE_mean = sd/√n (평가기가 `<kpi>_sd`, `n_episodes`를 보고).
- 공정 잡음(평가 간): σ_proc = 1.4826·MAD(∇²J)/√6 (v4, 7회 평가 이후 유효).
- σ = max(σ_meas, σ_proc). 첫 평가부터 오차막대가 있다(v4는 7회까지 σ̂=0).
- 롤백 허용치 τ = min(max(τ₀, z√2·σ), τ_max), τ₀=0.05, z=2, τ_max=0.3.
- **순차 검정**: ΔJ = J_{k+1} − J_k. ΔJ < −τ → 롤백. −τ ≤ ΔJ < −c·τ (c=0.5, 모호 구간) →
  새 에피소드로 m회(기본 1) 확인 재평가, 풀링 평균 J̄로 재판정(평균의 sd는 σ/√(m+1)).
  거짓 롤백(잡음)과 거짓 유지(진짜 손상)를 동시에 줄인다. 시뮬레이션 시간만 쓴다.

### 3.2 개입 효과의 추세 제거 귀속과 원장(ledger)
개입 전 같은 계보의 마지막 p=4개 평가에 OLS 기울기 β̂를 맞추고,

    effect = (J_after − J_before) − β̂·Δt

즉 "아무것도 안 했어도 올랐을 만큼"을 뺀 순효과. 상승 곡선에 올라탄 무해한 개입은 ≈0,
학습을 멈춘 개입은 J가 안 떨어졌어도 음수가 된다. 각 (파라미터, 방향) 쌍에 정규-정규
갱신으로 사후분포를 유지한다:

    μ_n = (μ₀/s₀² + Σ e_i/σ_i²) / (1/s₀² + Σ 1/σ_i²),   s_n² = 1/(1/s₀² + Σ 1/σ_i²)

σ_i = √2·σ(개입 시점), 사전 N(0, 0.1²)(설정 `effect_prior`로 (파라미터, 방향)별 지정
가능 — 예: 로그 연구의 방향별 ΔJ). 한 번의 행운이 지배하지 못하고, 시도 안 한
파라미터는 사전분포를 보고한다. 리포트에 "energy.weight up: effect on J +0.031 ± 0.045
(3 obs)"처럼 표시.

### 3.3 목적함수 headroom과 명령 상한
항 m이 파라미터 c의 명령을 받으면(`kpi_command`) 런 내 리포트 중 성공률 ≥0.5인 (c_i, v_i)
쌍으로 원점 통과 추종률 r̂ = Σc_i v_i / Σc_i²(관측이 없으면 사전값 0.89, 3·4차 462건)을
맞추고

    ceiling_m(c) = w_m·r̂·c,   ∂J/∂c ≈ w_m·r̂

를 보고한다: "+0.5 × 0.56 = +0.28 now; ceiling +0.30 at target = 0.7, +0.65 at its maximum
1.5; each +0.1 of target is worth up to +0.045 J if success holds", 그리고 지금까지
관측한 (명령, 측정, 성공률) 쌍을 나열해 속도–성공률 트레이드오프를 LLM이 데이터로
보게 한다. 성공률 항은 ceiling = w(headroom = w(1−p)). 파라미터 범위 하에서의 J 상한도
같이 적는다.

### 3.4 학습곡선 예측
현재 계보의 J 궤적에 포화 곡선 J(t) = A + B·e^{−(t−t₀)/τ}를 맞춘다(τ는 로그 격자 40점,
A·B는 각 τ에서 최소제곱 폐형해, R² 보고). 리포트에 "이 계보는 A로 수렴 중(시상수
τ), 예산 끝의 예상 J = …". 상한(3.3)과 나란히 보이므로 "아직 오르는 중"과 "상한 아래에
포화"를 구별할 수 있고, 남은 리포트 수와 함께 커리큘럼 변경이 회복될 시간이 있는지
계산할 수 있다.

### 3.5 단계 스케줄과 커리큘럼 복귀 불변식
- 단계: explore(<50 %) → exploit(50–85 %: 원장에 증거가 있는 수를 우선) →
  consolidate(≥85 %: 보상 변경은 시스템이 폐기, `curriculum_params`와 `algo.*`만 통과).
  마지막 15 %의 보상 변경은 회수될 시간이 없고 최종 평가만 흔든다.
- **불변식**: 커리큘럼 레버 ℓ(기준값 b)에 대해, 진행률 ≥ 50 %이고 최근 두 리포트의
  성공률 ≥ 0.3이며 ℓ < b이고 스케줄러가 이번에 ℓ을 건드리지 않았으면 시스템이
  ℓ ← min(b, ℓ·(1+0.3))로 한 가드레일 스텝 되올린다(리포트당 1스텝, 롤백 검정 적용).
  4차 stairs의 손실 전부(속도항 0.15)는 이 한 가지의 부재였다. LLM에는 "불변식에 맡기지
  말고 증거가 있으면 먼저 올려라"고 알린다.

### 3.6 예측 보정(calibration)
LLM은 행동과 함께 `predicted_delta_j`(추세 제거 순효과의 점예측)를 낸다. 시스템이
실현 효과와 비교해 부호 정확도·MAE·편향을 다음 리포트에 돌려준다("Your dJ predictions
so far: sign correct 67 % of 6, MAE 0.041, bias +0.02"). 자기 예측이 채점되는 것을 아는
모델은 과신을 줄이고, 논문에는 "LLM 예측 정확도"라는 지표가 하나 생긴다.

### 3.7 v4 결함 ↔ v5 장치 대응

| v1–v4 결함 | v5 장치 |

| 잡음에 롤백·복원 (v2) | 측정 SE + 공정 잡음 결합, 모호 구간 확인 재평가 |
| 같은 스냅샷 반복 복원 (v3) | (v4 유지) 스냅샷당 1회 + best 2회 확정 |
| 커리큘럼 내리고 안 올림 (v4) | headroom·명령 상한 표시(3.3) + 복귀 불변식(3.5) |
| 개입 효과를 추세와 혼동 | 추세 제거 귀속 + 원장(3.2) |

   동기 v5 재측정(§5의 재시작 절차)이 이를 가른다.
2. **동기 복귀는 개입 수를 되돌렸지만(16 vs 8) J를 올리지 못했다.** 개입이 잦아진 만큼

3. **원장 결함(s1).** 22M의 0.95→1.2(+26 %) 상향이 다음 리포트 성공률 하락으로 롤백되고,

   noop만 냈다(성공률 96~98 %, 속도 1.02). 그러나 같은 런에서 26M 0.95→1.0 이동은 두

외삽을 뺀 값을 두 번째 원장에 넣고, 증거 블록에 "Settled effect of curriculum moves" 줄로
붙인다(`coach.py::_settled_rows`, 관측 sd는 √2·σ). 창 안에서 같은 레버를 다시 만졌거나
롤백·복원이 있었으면 그 창은 버린다(깨끗하지 않음). `v5p`에서 `settled_reports: 2`로 켜고

### 6.1 v6 stairs-medium 결과와 원장 거부권(ledger veto)

| stairs, 40M | s0 | s1 | s2 | 평균 ± sd |
|---|---|---|---|---|
| v5 J | 1.126 | 1.163 | 1.008 | 1.099 ± 0.081 |
| v6 J | 0.938 | 0.245 | 0.833 | 0.672 ± 0.374 |
| ΔJ v6−v5 | −0.188 | −0.918 | −0.175 | −0.427 ± 0.425 |

n=3, 95% CI [−1.484, +0.630], p=0.22, d=−1.00. 세 시드 모두 −0.05 아래이므로 AcceptRule의
"설정별 −0.05 미만 없음"에 걸려 v6는 naive 결과와 무관하게 기각된다.

- **s0 — 탈출은 빨랐고 복귀가 느렸다.** STUCK 해체(10M target 0.343, stability −0.65,
  termination −13) 뒤 첫 성공 14M(v5 s0 25M). 그러나 16M·20M 롤백, 24·26M noop 뒤 28M부터
  0.446→1.0까지 ±30 % 스텝 5회 — 40M에 1.0 도달에 그쳤다(v5 s0는 29M). "stairs target_ms
  미복귀"(§2 v3 결함)의 재현이며 정착 원장이 겨냥한 구간이다.
- **s1 — 원장을 무시한 페널티 강화.** 6M부터 stability를 −0.65→−0.845→−1.1→−1.43→−1.86,
  termination을 −10→−13→−16.9→−22→−28.6까지 여섯 번 강화했다. 그동안 리포트의 원장은
  "stability.weight down: effect on J −0.085 ± 0.006 (5 obs)"였고 J는 0.35(8M)→0.12(30M)로
  단조 하락, 최종 성공률 0.05. 모델의 진단("낙상 99 % → 안정성·낙상 페널티 강화")은
  증거와 정반대였다. STUCK 프로토콜의 "가장 큰 페널티는 남긴다"를 "키운다"로 읽은 것도
  한몫했다.
- **s2 — 24M까지 target 0.3~0.49를 오르내리며 페널티 해체·강화 반복(롤백 2회), 30M에야

**조치 — 원장 거부권(`coach.ledger_veto_obs`, 기본 0=끔).** 제안된 보상 가중치 이동의
방향이 이 런의 원장에서 이미 유의하게 음수(사후 평균 + z·sd < 0, z=`ledger_veto_z` 2.0,
관측 ≥ k)이면 가드레일이 떨어뜨리고, 이력 줄에 `[guardrail: … vetoed by the ledger …]`로
보여 준다(`coach.py::_ledger_veto`). 커리큘럼 레버는 제외(즉시 효과가 구조적으로 편향).
같은 김에 이력 줄에 가드레일이 떨어뜨린 이동("dropped" 노트: 조정 불가·개수 초과·
consolidate 동결·거부권)을 모든 버전에서 보이게 했다 — 지금까지 모델은 자기 이동이
잘렸는지 params 차이로만 알 수 있었다. v5p에 `ledger_veto_obs: 3`과 system.md 문장을

### 6.5 적응 KL 페널티 폭주 — naive 바닥의 알고리즘 측 원인 (2026-09-08 오전)

v7 naive s1이 결과 없이 끝난 원인: 37M에서 `actor.dist` NaN으로 학습 붕괴. 손실이 22.9M부터
1e3을 넘고(코치가 20M에 LR 0.0006, 24M에 0.001로 올린 직후) 1e14~1e31까지 커졌으며
`train/kl_penalty`가 1.5e20이었다. `algorithms/ppo.py`의 PPO-penalty 스케줄(KL > 1.5·목표면
β×2, < 목표/1.5면 β×0.5)에 상·하한이 없었다. 평탄한 보상 바닥에서는 갱신 KL이 목표(0.01)를
계속 넘으므로 β가 매 갱신 두 배씩 지수적으로 커져 손실을 지배하고 정책을 얼린다.

`train/kl_penalty` 조사(β 최댓값 / β ≥ 64 도달 시점 / 첫 성공 / 최종 J):

| 런 | β max | β ≥ 64 | 첫 성공 | 최종 J |
|---|---|---|---|---|
| 컨트롤 naive s0 / s1 / s2 | 1e3 / 1.6e4 / 5.2e5 | 23M / 20M / 25M | – | 바닥 |
| evolve2 v5 naive s0 / s1 / s2 | 8.8e12 / 4 / 1e3 | 28M / – / 33M | – | 바닥 |
| evolve v5(구 스택) naive s0 / s1 / s2 | 512 / 1.5e20 / 128 | 24M / 23M / 35M | 10M / – / – | 0.988 / 0 / 0 |
| v6 naive s0 / s1 / s2 | 0.5 / 2 / 0.5 | – | – / – / 9M(재상실) | 바닥 |
| v7 naive s0 / s1 / s2 | 8 / 3e20 / 0.5 | – / 21M / – | – / – / 18M | 0.188 / 붕괴 / 0.980 |
| 건강한 rough·stairs 런 | 0.5~8 (최솟값 ~1e-30) | – | | |

바닥에 갇힌(또는 붕괴한) naive 런 13개 중 8개에서 β ≥ 64가 20~35M에 나타났고, 그 뒤 탈출한 런은 없다
(탈출 두 건은 β 폭주 전인 10M·18M). β 폭주가 바닥의 유일한 원인은 아니지만(v6 naive는
β ≤ 2인데도 바닥) 20M 이후의 탈출 불가능과 두 건의 붕괴(v5 s1, v7 s1)는 알고리즘 결함이다.
코치가 LR을 올리면 갱신 KL이 커져 폭주를 앞당긴다 — v7 s1이 그 경우다.

v8 rough까지 넣어 다시 보면 건강한 런에서도 후반에 β가 폭주한다: 20M 이후 갱신 KL 평균이
0.015~0.027로 목표(0.01)의 1.5배를 계속 넘으므로 β가 1e-25에서 갱신마다 두 배씩 회복해 32M쯤
O(1)을 지나 36~40M에 v8 s0 1.6e4, s2 4.1e3(손실 2e2)에 이른다(v7 s2는 8에서 끝남). 즉
`adaptive_kl`은 실제로는 학습 대부분에서 꺼져 있다가(β ≪ 1) 마지막 4~8M에 폭주하는
장치였고, 목표 KL 0.01이 이 문제의 자연 KL(~0.02)보다 낮게 잡혀 있다.

조치(`fix(ppo)`): `adaptive_kl.{penalty_min, penalty_max}`(기본 0 / **8**)로 β를 고정하고,
비유한 손실 미니배치는 건너뛰며(`train/nonfinite_minibatches`로 보고), 체크포인트 로드 시에도
고정한다. 상한 8은 잘 학습한 런이 도달한 최댓값(v7 s2)이라 그 아래 동역학은 이전과 같고,
하한을 두지 않은 것도 같은 이유(컨트롤과의 차이를 폭주 구간으로만 한정). `target_kl`을
자연 KL에 맞게 0.02로 올리거나 하한을 두는 것은 별도 실험 항목으로 남긴다. `tests/test_ppo.py`.

**검증(v8 naive, 상한 8): β 폭주는 naive 바닥의 원인이 아니다.** 상한 8로 돈 v8 naive 3런은 모두
바닥(성공 0, 최종 속도 0.232 / 0.24 / 0.22). 속도는 5M부터 40M까지 0.22~0.23으로 완전히 평탄
— 컨트롤(0.237 / 0.232 / 0.232)과 같은 값이며, β가 64를 넘는 20M보다 훨씬 전에 바닥이
확정된다. β는 8M부터 상한 8에 붙어 있었고(갱신 KL 0.011~0.025로 목표 초과가 지속) 정책은
계속 움직이는데 평가는 그대로다: 즉 naive 바닥은 보상 설계가 만드는 고정점(0.23 m/s 기어가기)
이고, 폭주는 그 위에서 일어나는 2차 현상이다. 코치의 한 파라미터씩 움직이기(v8 max_params 1)
로는 못 빠져나오며, 탈출 두 건(v5 s0 10M, v7 s2 18M)은 첫 리포트의 {target↓, energy↑,
action_rate↑} 동시 이동이라는 플레이북 소견과 일치한다. 수정은 그대로 둔다(붕괴 방지와
후반 폭주 제거가 목적). s2(stop_kl 0.2)는 26M LR 0.0006 상향 뒤 24~32M에 조기 종료 8회,
붕괴 없음.

**갱신 한 번에 KL 19 — 에포크 조기 종료(stop_kl).** 새 PPO(상한 32)로 돈 첫 런 v8 stairs s0에서
코치가 32.0M에 target 1.3→1.5로 올리자 32.8M의 한 갱신에서 approx_kl이 19(정상 0.01~0.06)로
튀고 33M 평가가 0.57→0.00으로 무너졌다(β는 그때 8e-3이라 상한과 무관; 롤백 뒤 37M에 0.57
회복, 최종 J 1.156). 보상이 갑자기 바뀌면 Adam이 일관된 방향으로 20스텝을 밟아 출력이
크게 움직이며, 비율 클리핑은 서로게이트 기울기만 막을 뿐 이 이동을 막지 못한다. 표준
안전장치인 KL 조기 종료(`adaptive_kl.stop_kl`, 기본 0.2: 미니배치 KL이 넘으면 그 갱신의
남은 에포크를 버림, `train/kl_early_stop`)를 추가했다. 건강한 미니배치 KL(≤0.06)의 3배
이상이라 정상 갱신에는 걸리지 않는다. 코치 쪽 교훈: 커리큘럼을 한 번에 두 단계(1.3→1.5)
올린 것이 방아쇠였고 즉시 원장에는 −1.04로 남는다(커리큘럼은 거부권 대상이 아니라 무해). 이 수정은 **학습 스택 변경**이므로 이후 런(코치 유무 모두)의 naive
결과는 이전 컨트롤과 직접 비교할 수 없다 — 새 루트에서 컨트롤을 다시 측정해야 한다
(`restart_sync.sh`의 컨트롤 심볼릭 링크를 쓰지 말 것).

| 버전 | playbook.enabled | settled_reports | ledger_veto_obs | curriculum_lock |

| v8, v9, v10 | **없음** | 없음 | 없음 | 없음 |

즉 v8·v9·v10의 짝 비교는 "v7p − 결정층 + 가설"을 v7p와 비교한 것이다. 그래서:
- v8 naive 1/3(§6.9)과 v9 naive 2/3(§6.11)은 max_params나 개입 상한 때문이 아니라
  **플레이북이 꺼진** 결과와 구분되지 않는다(플레이북 없는 v7은 1/3, 있는 v7p는 3/3).
- v9 stairs의 target 상향 연쇄·v10 rough s2의 하향은 **잠금이 꺼진** 결과일 수 있다.
- v8·v9의 "기각"은 가설을 검정하지 못했다. 다만 조리법 재집계(§6.11)로 v8의 가설
  (파라미터 수 축소)은 별도로 반박되고, v9의 가설(빈도 상한)은 stairs 병목이 방향이라는

  v10(release_min_success 0.5)은 stairs 방향 문제를 겨냥하므로 coach.yaml을 의도대로
  (v7p 오버라이드 + 0.5) 고쳐 evolve4 큐에 남긴다.

### 6.13 evolve4 — 수정된 스택에서 v7p 재측정 (2026-09-09 03:50)

evolve4 = evolve3 스택 + §6.10 β 하한 + §6.12 오버라이드 상속 + 조기 종료 수정. 대조군과
v7p를 같은 시드로 다시 돌렸다(`data/results/evolve4/`, 런당 ≈42 분).

| 설정 | none J (n=3) | v7p J (n=3) | 짝 ΔJ | evolve3 v7p |
|---|---|---|---|---|
| rough-hard/trad | 1.418 / 1.412 / 0.377 = 1.069 ± 0.600 | 1.647 / 1.623 / 1.634 = **1.635 ± 0.012** | +0.229 / +0.211 / +1.257 | 1.645 ± 0.016 |
| stairs-medium/trad | 0.995 / 1.021 / 1.043 = 1.020 ± 0.024 | 1.139 / 1.090 / 0.509 = **0.913 ± 0.350** | +0.144 / +0.069 / **−0.534** | 1.251 ± 0.064 |

합동 n=9: ΔJ **+0.678 ± 0.626**, 95 % CI ±0.481, 짝 t p = 0.037, Wilcoxon p = 0.039, d = 0.83
(evolve3: +0.762 ± 0.536, p 0.011, d 1.09). 속도 +0.586 (p 0.008, d 1.16), 성공률 +0.385
(p 0.079), 경로 효율 +0.063 (p 0.040), 낙상 −77/min (p 0.064). rough·naive는 시드별 0.02 이내로
재현됐고(naive 탈출 3/3, 첫 보고 조리법 3/3 적용, 8·12·8 M 탈출), **stairs만 재현되지 않았다**.
표: `paper/tables/table6_coach_per_setting_evolve4.csv`, `table7_coach_pooled_evolve4.csv`.

**stairs의 실제 병목 — release가 늦다.** 대조군까지 평가 궤적을 나란히 놓으면:
- 성공률이 0에서 처음 양수가 되는 시점(발현)은 **모든 stairs 런에서 18–38 M**이다: 대조군
  (target 1.0 고정) 24 / 18 / 28 M, v7p 21 / 24 / 38 M, evolve3 v7p s2 20 M. 발현 전에는 속도가
  0.7(코치)이든 0.9(대조군)든 성공 0 — 보상 파라미터가 발현 시점을 앞당긴 증거가 없다.
- 코치의 이득은 전부 발현 뒤의 **release 램프**에서 나온다. target 0.7→0.9→1.1→1.4가 2 M마다
  J +0.1~0.25(s1 28 M 0.43 → 34 M 1.02, s0 22 M 0.43 → 28 M 1.04), 최종 속도 1.1–1.3 m/s
  (대조군은 0.85–0.9에 고정). 발현이 21–24 M이면 램프 시간이 남아 +0.07~+0.14, evolve3 s2처럼
  20 M이면 +0.18.
- s2는 발현이 38 M이라 램프할 시간이 없었고, 그 전 20 M 동안 target 0.7 아래에서 속도 0.7,
  J 0.3에 묶여 대조군(속도 0.9, J 0.45)보다 −0.5. 16 M의 target 0.49 시도는 J 0.33→0.20으로
  롤백됐는데 evolve3 s2의 같은 이동(0.5 @ 10 M)은 유지되어 20 M 발현으로 이어졌다 — 잡음
  수준의 갈림이 −0.5를 만든다.
- 발현 전 8–26 M 구간에서 보상 가중치 미세조정 8–10회가 모두 τ 안이라 "kept"인데 누적으로
  J 0.39→0.26(best 복원이 s1 14 M, s2 24 M에 한 번씩). 개별 허용치가 누적 표류를 막지 못한다.

함의: v10(release_min_success 0.3→0.5)은 램프를 **더 늦추므로** 이 자료로는 stairs에
불리하다(s0·s1도 성공 0.5 도달이 29–33 M). 자료와 맞는 후보는 반대 방향 — "발현(성공률이 2회
연속 양수) 즉시 release 시작, 진행률 0.5 대기 없이" + "발현 전 stairs에서는 target을 대조군
값(1.0) 아래로 내리지 않기". v10 판정과 메타 LLM의 v11 제안이 이를 잡는지 본다.

스택 차이: 대조군 stairs도 1.093(evolve3)→1.020으로 내려갔다. β 하한 수정으로 적응 KL이
실제로 작동하면서 stairs 학습이 전반적으로 느려진 것으로 보이며, 논문에서는 evolve3와
evolve4를 별도 배치(같은 코치, 다른 PPO 스택)로 병기한다.
