## 5. 추정 — 코치 v4.1이 stairs에서 낼 J (측정 아님)

**방법.** v4.1의 변경점은 리포트에 "속도항은 명령 속도로 상한이 걸려 있다"를 수치로
보여주고 되올리기를 지시하는 것이다(§6). 그 효과를 실제 학습 없이 추정하려면
"코치가 target을 t까지 되올렸을 때 J"가 필요하다:

    J_cf(t) = 측정 성공률(시드별) + 0.5 · r · t

r = 명령 추종률. 3·4차 LLM 런의 리포트 중 (파라미터, KPI) 쌍이 일관되고 성공률
≥0.5인 462개에서 원점 통과 회귀 r = 0.893 (평균 0.883±0.058; rough-hard 0.855,
rough-medium 0.923, **stairs 0.857**, 단 stairs는 target 0.6–0.7 범위만 관측).
`figs/tracking.png`.

**결과** (`counterfactual_stairs.csv`, stairs LLM v4 5시드 재채점, none 측정 1.008 [0.82, 1.19]):

| 되올린 target (m/s) | J_cf mean±sd | 95% CI |
|---|---|---|
| 0.7 (현재) | 0.88±0.11 | [0.74, 1.02] |
| 1.0 (기본 명령) | 1.01±0.11 | [0.88, 1.15] |
| 1.2 | 1.10±0.11 | [0.97, 1.24] |
| 1.5 (rough 수준) | 1.24±0.11 | [1.10, 1.37] |

**해석과 한계.** target을 기본값 1.0으로만 되돌려도 none과 동등(1.01 vs 1.01)이고,
rough에서 실제로 했듯 1.5까지 올리면 +0.23이다. 이 추정은 두 가정에 의존한다:
(a) 성공률이 명령 속도에 둔감하다 — stairs에서 target 0.7의 LLM(0.566)과 1.0의
none(0.573)이 같으므로 0.7–1.0 구간은 뒷받침되지만 **1.0 초과는 미검증**(계단에서
빠른 속도가 낙상을 늘릴 수 있음); (b) 추종률이 target과 무관 — rough 0.6–1.5에서
0.85–0.92로 일정했다. 따라서 논문에서는 "1.0 복귀 시 none 동등, 그 이상은 가설"로만
쓴다. 이 값은 v4.1 런의 결과가 아니며 그렇게 표기해서는 안 된다.

## 6. 제시 — 코치 v4.1 아키텍처 (구현 완료, 로컬 Isaac 스모크 검증, 미실행)

```
매 2M 스텝:  결정적 평가(256 env) ─┐
                                   ▼
   판단층(코드)  ── 잡음 σ̂(2차 차분 MAD) → 허용치 max(0.05, 2√2σ̂)≤0.3
                ── best = 연속 2회 평균, 스냅샷당 복원 ≤1
                ── 롤백: J < J_before − 허용치
                ── API 오류: 30/60/120 s 재시도 → 리포트 스킵(학습 계속)
                                   ▼
   리포트  ── KPI, 학습 통계, PPO 동역학, 개입 이력, 잡음 추정
           ── [v4.1] 목적함수 분해: 항별 기여 + kpi_command 상한
              "+0.5 × 0.56 = +0.28; commanded by target_ms = 0.7
               (measured/commanded = 0.80) — capped near +0.35 until raised"
                                   ▼
   LLM(gpt-5.4, reasoning high) ── JSON {diagnosis, actions≤3, restore_best, confidence}
           ── [v4.1] 규칙: 내린 target은 목표 도달 후 단계적으로 되올려라
                                   ▼
   가드레일 ── 범위·부호 잠금, 선형 ±30 %/로그 ×3, 클리핑 → 적용(보상 + algo.*)
```

설정: `configs/coach/llm.yaml`의 `kpi_command`, `tracking_ratio`, `noise_*`,
`best_confirm`, `max_restores_per_snapshot`, `llm.api_retries/api_backoff_s`.
테스트: `tests/test_coach.py`(20), `tests/test_coach_study.py`(4).

## 8. 비용 0으로 v4.1을 실측하는 길

1. **로컬 오픈 모델을 코치로**: 서버 4×4090 중 1장에 Qwen/Llama 계열 30B급(4-bit)을
   ollama/vLLM으로 띄우면 OpenAI 호환 API라 `llm.base_url`만 바꾸면 된다. GPU 시간은
   무료, 논문에는 "모델 조건" 하나가 추가된다(GPT vs 오픈 모델).
2. **증류 코치(distilled coach)**: 3·4차 로그의 LLM 결정을 규칙으로 증류 —
   "성공 0이면 target 0.7, 성공 ≥0.8이 2회 연속이면 target ×1.3(≤1.5)" + naive 보상의
   페널티 설계 — API 없이 실행. "LLM이 찾은 커리큘럼을 규칙으로 재현할 수 있는가"라는
   별도 연구 질문이 되며, §5 추정의 가정 (a)를 실측으로 검증한다.
